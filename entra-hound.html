ENTRAHOUND

WHO CAN ULTIMATELY CONTROL WHAT

EntraHound turns a Microsoft Entra ID tenant into a directed security graph: every identity, group, role, application, workload, device and AI agent is a node; every membership, ownership, role, credential, permission and trust is an edge. Then it asks the only question that matters — which combinations create a path to your critical assets? Read-only, browser-only, nothing leaves your machine.

Connect with your app registration

Delegated sign-in through a single-page-application registration in the tenant you want to assess. What EntraHound can see is the intersection of the app's consented permissions and your own directory role — a Global Reader or Security Reader is enough; Global Administrator is never required.

App registration setup
  • Platform: Single-page application, redirect URI exactly https://blue16.nl/entra-hound.html
  • Required delegated permission (admin consent): Directory.Read.All — the whole core graph is built from it.
  • Optional, each unlocks more edges and findings: Policy.Read.All, RoleManagement.Read.Directory, AuditLog.Read.All, UserAuthenticationMethod.Read.All, AgentIdentityBlueprint.Read.All, AgentIdentity.Read.All, AgentIdentityBlueprintPrincipal.Read.All. The full matrix is under Collection.
  • MSAL cannot run from file://; serve the page over http(s).

Bring a token minted outside the browser

A browser cannot run the client-credentials flow (secrets, certificates and managed identities need a confidential client and the token endpoint blocks CORS). Mint an access token for https://graph.microsoft.com with whatever identity you want the collector to run as, paste it here, and EntraHound uses it read-only. The token stays in this tab's memory.

How to mint one
  • Certificate / secret (app-only): Connect-MgGraph -ClientId <id> -TenantId <tid> -CertificateThumbprint <thumb> then ConvertFrom-SecureString (Get-MgContext | % { (Get-MgAccessToken) }) -AsPlainText — or with Azure CLI: az login --service-principal -u <id> -p <cert.pem> --tenant <tid> and az account get-access-token --resource-type ms-graph --query accessToken -o tsv.
  • Managed identity (from an Azure VM/App Service/Function): az login --identity then the same get-access-token.
  • Application permissions to grant: the same list as the delegated ones, as Application permissions. Least privilege is Directory.Read.All alone.
